# 实验报告：多边形扫描转换

> 作业 1 · 计算机图形学 · 2026-09-14

## 一、任务与目标

实现简单多边形的扫描线填充：读取顶点（文本文件或交互输入），构造边表与活性边表，逐条扫描线求交点、排序并成对填充，最终输出同时包含**边界**与**内部区域**的结果图；对水平边、共享顶点、极值点、不同斜率以及非法输入均需稳定处理。

## 二、实现环境

| 项 | 值 |
|---|---|
| 语言 / 标准 | C++17 |
| 编译器 | GCC 14.2（MinGW-w64），`-O2` |
| 构建 | CMake 3.16+ / Ninja |
| 平台 | Windows（Win32 GDI 窗口） |
| 第三方依赖 | 无（PNG 编码亦自行实现） |

## 三、数据结构

**边（Edge）**：`yMin`、`yMax`（区间下端/上端）、`xAtYMin`（下端处 x）、`invSlope`（dx/dy），以及派生的 `enterScanline`（开始参与的扫描线）、`leaveScanline`（不再参与的扫描线）。

**边表 ET**：`vector<vector<int>>`，按 `enterScanline` 分桶，桶内存边下标。构造时**跳过水平边**（与扫描线重合，不产生有效交点）。

**活性边表 AET**：`vector<int>`，保存当前扫描线正在穿过的边下标。每推进一行：
① 把 ET 中属于本行的边插入 AET；② 把满足 `y ≥ leaveScanline` 的边移除。

**填充区间 Span**：一行内若干 `[xStart, xEnd]`（闭区间、像素单位）。

## 四、扫描线规则（本实现的核心约定）

1. **像素覆盖**：像素 `i` 覆盖 `[i, i+1)`，以中心 `i+0.5` 作为采样点。
2. **y 方向半开区间**：非水平边参与求交的判据是 `yMin ≤ y + 0.5 < yMax`，即下端算、上端不算。
3. **水平边**：直接跳过。
4. **x 方向半开区间**：一行内按 `[xl, xr)` 取像素（左闭右开）。
   由此 `xStart = ceil(xl − 0.5)`、`xEnd = ceil(xr − 0.5) − 1`。

**为什么需要 2 与 3**：若不做半开约定，"顶点恰好落在扫描线上"时同一顶点会被两条边各算一次，导致该行交点数为奇数、填充溢出。采用半开区间后，局部极值点处两条边同时进入（V 形尖端）或同时退出（Λ 形峰顶），交点个数恒为偶数，无需任何"顶点特判"代码。

**为什么需要 4**：交点区间若取闭区间 `[xl, xr]`，当像素中心恰好落在边上时会多填一列；改为左闭右开即可与"像素覆盖 `[i, i+1)`"的约定自洽。这一点是**对照独立实现后发现并修正**的（见第六节）。

**交点计算**：`x = xAtYMin + invSlope · (y + 0.5 − yMin)`，由边参数直接计算，不做"每行累加 `invSlope`"的增量更新，故长边上没有累积误差。

## 五、流程

规范化顶点（剔除相邻重合点、识别末尾重复的闭合点）→ 校验（顶点数 ≥ 3、面积非 0、无自交）→ 自动闭合 → 建 ET → 逐扫描线（ET→AET、求交、排序、成对生成区间、写像素）→ **填充后再画边界**（让边界覆盖在填充层之上）。

## 六、测试与现象

**单元测试**（`ctest`，共 96 项检查，全部通过）：

- `test_raster`（65 项）：画线八个方向；轴对齐矩形逐行区间精确值；**凸五边形 / 凹 L 形 / 10 顶点星形 / 菱形与"独立射线法实现"逐像素对照，漏填 0、多填 0**；菱形逐行像素数呈单峰（验证共享顶点与极值点未重复计数）；闭合点重复与相邻重合；逐行推进与一次性填充结果一致；四类非法输入；高度不足 1 像素的退化输入。
- `test_png`（31 项）：CRC-32 与 Adler-32 标准测试向量、IHDR 字段、全文件逐块 CRC 重算。

**端到端验证**：程序输出的 PNG 用 Python 标准库 `zlib`（独立实现）解压后逐字节比对 —— 块 CRC 全部通过，像素值与写入一致；填充像素数与解析值（世界面积 × 缩放²）偏差 **-0.35%**（凸五边形：241784 vs 242635）与 **-1.03%**（凹箭头：109656 vs 110801），差值恰为被边界覆盖的像素，符合"先填充、后画轮廓"的约定。

**边界情形与错误处理**（实测）：

| 用例 | 现象 |
|---|---|
| 凸/凹多边形 | 正常填充，凹口未被填充 |
| 末尾重复首点 | 规范化后顶点数减 1，不产生零长度边 |
| 顺时针输入 | 正常填充（奇偶规则与方向无关），终端提示可改为逆时针 |
| 蝴蝶结自交 | 退出码 4，提示"多边形自交：不是简单多边形" |
| 三点共线 | 退出码 4，提示"顶点共线：多边形面积为 0" |
| 顶点数不足 | 退出码 3，提示顶点数错误（含行号） |
| 文件不存在 / 格式错误 | 退出码 3，给出文件名或**出错行号与内容** |
| 高度不足 1 像素 | 合法但无扫描线可填，输出仅轮廓（不崩溃） |

**动画演示**：`--window --animate` 逐条扫描线推进，高亮当前扫描线，身后留下已填充区域，可直观看到"每一行只处理与它相交的边"。

## 七、复杂度

建表 `O(E)`；每行排序 `O(A log A)`；总体 `O(E + Σ_y A log A)`（最坏 `O(E·H)`）；空间 `O(E + A)`。实际耗时主要在逐像素写出（与填充面积成正比）。

## 八、已知限制与改进方向

- 仅支持单个简单多边形；带孔/多轮廓可改为"多轮廓统一求交 + 奇偶或非零绕组规则"。
- 边界为硬边（无抗锯齿）；可按像素覆盖率做灰度/alpha 混合。
- PNG 使用 zlib 存储块（不压缩），文件约为 `宽×高×3` 字节；如需压缩可实现固定 Huffman 或 LZ77。

## 九、小结

扫描线算法本身不长，难点集中在**边界一致性**：水平边、共享顶点、极值点、像素中心采样与区间开闭方向，任何一处不统一都会表现为"漏填一列/多填一列/尖角处溢出"。本次实现用一套统一约定（像素覆盖 `[i,i+1)` + y 半开 + 水平边跳过 + x 左闭右开）一次性覆盖了这些情形，并通过"与独立射线法实现逐像素对照"的测试把约定钉死，使得边界情形的正确性可以被自动验证，而不是靠肉眼观察。
