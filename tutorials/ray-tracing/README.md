# ray-tracing —— 用 gfx 自己渲染光线跟踪图（光照 + 反射/折射 + 阴影 + BVH + 超采样）

> **用途**：演示如何用 `gfx` **脱离任何外部框架**自己渲染出一张光线跟踪图像：光照模型（[`gfx/render/lighting.hpp`](../../../src/include/gfx/render/lighting.hpp)）+ 递归跟踪器（[`gfx/render/raytracer.hpp`](../../../src/include/gfx/render/raytracer.hpp)），相机用 [`gfx::View`](../../../src/include/gfx/render/view.hpp) 的 `pixelToRay` 生成主光线，场景用 [`gfx::Bvh`](../../../src/include/gfx/geom/bvh.hpp) 加速，最后 [`gfx::savePng`](../../../src/include/gfx/render/png.hpp) 落盘。
> **目标读者**：学完"光线求交地基"后，想看"光照 + 递归"如何真正拼成一张图的读者。
> **关联文档**：[adr-0011](../../../docs/design/adr-0011-ray-geometry.md)（求交与 BVH）、[adr-0012](../../../docs/design/adr-0012-raytracing-lighting.md)（光照与递归跟踪的决策）。

> 状态：新增（2026-10-09）。

## 这一节在讲什么

- **上色**：每个像素射出一条主光线，取最近命中，用 `gfx::shadeLocal` 做局部光照——环境光 + 自发光 + 逐光源 Lambert 漫反射 + Blinn-Phong 高光，逐光源做**阴影测试**。
- **递归**：`gfx::RayTracer::trace` 在命中镜面/玻璃时递归发射**反射**与**折射**光线，做深度控制；全反射时不产生折射光。
- **解耦**：跟踪器不知道场景里有什么——"某个方向是否命中物体"由调用方以**求交回调**注入（`RayTracer::HitFunction`）；阴影射线复用同一回调。于是几何层、BVH 与光照层彼此独立。
- **相机**：复用第一阶段的 `View::lookAt` + `setPerspective` + **`pixelToRay`**（屏幕像素 → 世界射线），这正是"像素 → 主光线"的权威来源。
- **抗锯齿**：每像素 3×3 子采样（子像素中心），取平均。

## 场景

| 类别 | 内容 |
|------|------|
| 地面 | 无限平面 `y = -1`（法向 +y），带轻微反射 `ks = 0.12` |
| 镜面球 | 高反射 `ks = 0.85`（会映出地面/立方体/其它球） |
| 玻璃球 | 透明 `kt = 0.9`，折射率 `n = 1.5`（可看到穿透与全反射） |
| 红球 | 普通漫反射（`diffuse` 偏红） |
| 立方体 | 轴对齐盒（用 `intersectAabb` 求交、按命中面定法向），暖橙色 |
| 圆柱 | `intersectCylinder`（任意轴 + 两端圆盖），蓝色 |
| 不规则晶体（半透明） | **三角网格**（正八面体骨架各顶点扰动 + 绕 Y 轴旋转 ⇒ 外形不规则）；8 个面**各自带材质**——`+x` 侧 4 面透明（`kt = 0.9`、`n = 1.55`），`-x` 侧 4 面实心（不透明深青绿）⇒ **一半透明、一半实心**；用 `intersectTriangle` 逐面求交取最近，面法向由顶点顺序保证朝外 |
| 悬浮透明球 | 前景玻璃泡（`(0.70, 0.40, 2.40)`、`r = 0.36`，`kt = 0.92`、`n = 1.45`），悬在相机（`z = +4.6`）与场景之间，**只遮住右侧三个物体的一部分** |
| 3 块凸透镜 | **双凸透镜 = 两颗球的交集**（`intersectLens`）：由通光半径 `A = 0.28`、中心厚 `T = 0.078`、`n = 1.5` 反解曲率半径 `R = (A² + T²/4)/T ≈ 1.025`、球心距 `R − T/2`（镜边两球恰好相切）；厚透镜焦距 **f ≈ 1.038**。三块**同规格**、只是物距不同：`u = 0.7f / 1.5f / 3f`，各瞄准一个物体（视线互不重叠） |
| 光源 | 5 个彩色点光源：暖白主光 + 暖色补光 + 冷色轮廓光 + 前排暖补光 + 近景冷补光 |

## 怎么运行

```bat
:: 1) 构建（产物 build/tutorials/RayTracing.exe）
cmake --build build --target tutorial_ray_tracing

:: 2) 渲染并保存 PNG（父目录会自动创建）
build\tutorials\RayTracing.exe --output tutorials\ray-tracing\output\ray-tracing.png
```

参数：

- `--output <png>`：结果 PNG 路径（默认 `output/ray-tracing.png`）。
- `--size WxH`：画布尺寸（默认 `800x600`）。
- `--samples n`：每像素 n×n 超采样（默认 `3`，`n=1` 关闭）。
- `--depth d`：递归深度（默认 `6`）。
- `--brute`：额外跑一遍"关掉 BVH 的暴力法"做逐像素一致性校验（**默认关闭**，约多花一倍时间）。
- `--help`：显示帮助。

> 无参数直接双击运行时按默认设置渲染，结束会打印输出路径并停在"按回车键退出"（仅当 stdin 是终端才停，脚本/管道调用不受影响）。
> 渲染过程每 50 行打印一次进度百分比（与课程框架 `render_scene` 的做法一致）；Windows 下启动时会把控制台输出切到 UTF-8，保证中文不乱码。

## 交互版：窗口内实时调相机

同目录的 [ray_tracing_interactive.cpp](code/ray_tracing_interactive.cpp) 用 [`gfx::Window`](../../../src/include/gfx/render/window.hpp) 做实时交互；场景与离线版**共用同一份定义**（[ray_tracing_scene.hpp](code/ray_tracing_scene.hpp)：材质 / 图元 / BVH / 求交 / 相机），避免两份代码各改各的。

```bat
cmake --build build --target tutorial_ray_tracing_interactive
build\tutorials\RayTracingInteractive
```

| 操作 | 作用 |
|------|------|
| 左键拖动 | 转视角（yaw / pitch） |
| 右键拖动 | 平移相机（沿视线的右 / 上方向） |
| W / S | 上升 / 下降（沿世界竖直方向） |
| A / D | 左右平移 |
| 滚轮 | 前后推拉（dolly，沿视线方向） |
| R | 相机复位 |
| 空格 | 用高质量参数渲一张并存 `ray-tracing-interactive.png` |
| Esc | 退出 |

参数：`--size WxH`（预览窗口尺寸，默认 `480x360`）、`--frames N`（渲 N 帧后自动退出，冒烟测试用）、`--help`。

预览用 **1 采样 + 递归深度 4** 换帧率（本机实测 480×360 约 7.5 fps、320×240 约 13 fps）；按空格出图用 800×600、3×3 超采样、深度 6。相机用 yaw/pitch 描述朝向，初始值与离线版的 `lookAt` 取景一致。

## 凸透镜与三个成像区间

场景里放了 3 块**同规格的双凸透镜**，物距分别落在三个区间，用来观察成像规律。

**图元实现**：透镜没有单独的解析式，用「**两颗半径 R 的球求交集**」表达（`intersectLens`）——
分别求射线与两球的实心区间、取交集就是"在透镜内"的区间；进入与射出都返回最近的正向交点且法向朝外，
再由跟踪器做**两次 Snell 折射**完成会聚。由通光半径 `A`、中心厚 `T` 反解
`R = (A² + T²/4)/T`、球心距 `= R − T/2`（镜边两球恰好相切，边缘厚度 0）。

**透镜参数与独立验证**（`A = 0.28`、`T = 0.078`、`n = 1.5` ⇒ 厚透镜公式 f = 1.038）：

| 检查项 | 结果 |
|--------|------|
| 由 R、球心距反解通光半径 | **0.2800**（目标 0.28）|
| 轴向射线入口位置 | **−0.0390** = −T/2 |
| 镜外射线（径向 0.40 > A） | **不命中** |
| **平行光束经两次折射后的会聚点** | r=0.05 → **1.047**；r=0.10 → **1.035**；r=0.25 → **0.945** |

最后一行是关键：近轴焦点 1.035 与公式 1.038 吻合，且半径越大焦点越前移 ⇒ **球差**，
正是厚双凸透镜应有的物理行为（说明法向、两次面交互与折射口径都没错）。

**三块透镜与预期现象**（u 为物距、v 为像距、m 为放大率，由薄/厚透镜公式算出）：

| 透镜 | 目标物体 | u | u/f | v | m | 预期现象 |
|------|----------|---|-----|---|---|----------|
| L1 | 红球 | 0.727 | 0.70f | −2.42（同侧虚像）| **+3.33** | 正立放大的**虚像**（放大镜）|
| L2 | 镜面球 | 1.556 | 1.50f | +3.11 | **−2.00** | 倒立放大的**实像** |
| L3 | 圆柱 | 3.113 | 3.00f | +1.56 | **−0.50** | 倒立缩小的**实像** |

相机到 L2 的距离 5.02 > v=3.11、到 L3 的距离 2.86 > v=1.56 ⇒ **相机都落在实像之后**，
所以"倒立"是能被观察到的（不是只在理论上成立）。

**实拍对照**：三块透镜的屏幕圆（L1 (268,273) r=33、L2 (435,259) r=44、L3 (302,333) r=77）内，
像素相对"无透镜基线"分别变化 **85% / 97% / 88%**（平均通道差 64 / 43 / 100），
即透镜确实在强烈成像而非看不见。

## 结果（实测）

800×600、3×3 超采样、`maxDepth = 6`，在本机（MinGW-w64 + Ninja，Release）实跑的原始输出（默认不带 `--brute`）：

```

  分辨率        : 800x600（每像素 3x3 = 9 条主光线，共 4320000 条）
  递归深度      : 6
  场景图元      : 球 x4（镜面 ks=0.85 / 玻璃 kt=0.9,n=1.5 / 漫反射 / 悬浮透明 kt=0.92,n=1.45） + 立方体 x1 + 圆柱 x1 + 不规则晶体（8 三角面：一半透明 kt=0.9,n=1.55、一半实心） + 凸透镜 x3（双凸 = 两球交集，n=1.5；物距 u = 0.7f / 1.5f / 3f）（以上入 BVH）+ 无限地面 x1
  光源          : 5 个彩色点光源
  BVH           : 节点 7 / 叶子 4
  主光线命中像素: 407200（占 84%）
  平均每像素    : BVH 精确求交 182.761 次 / 节点访问 225.557 次（含超采样与递归）
  渲染耗时      : BVH 3347.56 ms（已跳过暴力法对比）
  输出          : tutorials\ray-tracing\output\ray-tracing.png
```

加 `--brute` 会额外跑一遍"关掉 BVH 的暴力法"做一致性校验，并多打印这几行（示例）：

```
  渲染耗时      : BVH 3860.64 ms   暴力法 8531.83 ms   （BVH/暴力 = 0.452498）
  暴力法求交    : 平均每像素 510.815 次（= 图元数 7 次/查询）
  两图一致性    : 完全一致（0 不同像素）
```

产物：`output/ray-tracing.png`（800×600）。

## 与作业三的关系

本示例把作业三里"手写的那些公式"换成了 gfx 的库函数，**数值口径刻意保持一致**（见 [adr-0012](../../../docs/design/adr-0012-raytracing-lighting.md) 与 `tests/test_raytracer.cpp` 的"作业三对齐"用例）：

- 法向定向 `N·d > 0 ⇒ N = -N`；自交偏移 `P ± N·1e-4`；
- 漫反射 `diffuse ⊙ 光色·强度·max(0,N·L)`；高光 `specular ⊙ 光色·强度·pow(max(0,N·H), shininess)`；
- 环境光 `0.05·diffuse`；反射 `R = d - 2(d·N)N`；折射 `eta = inside ? n : 1/n`，`k < 0 ⇒ 全反射`；
- 合成 `local + ks·reflected + kt·transmitted`，末尾 `clamp(0,1)`。

`tests/test_raytracer.cpp` 用 gfx 的类型与函数重跑了作业三的 7 组数值用例（空场景 / 球距离与法向 / 漫反射手算 / 阴影 / 45° 反射 / 全反射 / 圆柱命中），逐条打印"期望 vs 实际"，全部一致（详见下方"与作业三对齐"片段），证明"用我们自己的库能得到与课程框架一致的数值结果"。

## BVH 与超采样的实测收益（如实报告）

- **求交次数（确定性指标，可靠）**：本场景 7 个图元（4 球 + 1 盒 + 1 圆柱 + 1 八面体网格）+ 1 个地面，BVH 的"精确求交次数"是暴力法的约 **47%**（241.27 vs 510.82 次/像素，含超采样与递归；5 个光源让阴影射线变多，两类计数都比 3 光源时更高）。该数字每次跑完全一致。
- **墙钟测量在本机上噪声很大，不作为结论**：同一场景、同一参数重复测量，`BVH/暴力` 比值在 **0.45–1.00** 之间跳（实测例：3861 vs 8532 → 0.45；4402 vs 4481 → 0.98）——差异来自机器负载而非算法。**故本教程不宣称任何加速比**；只能说本场景规模小（7 图元），BVH 的节点遍历开销（139.11 次/像素）与剪枝收益是同一量级，墙钟大概率落在 1× 附近。要看到稳定收益需要更大的场景（`tests/test_ray.cpp` 的随机场景里，200/2000 个盒的 BVH 回调数比暴力法少 99%+）。
- **正确性不打折**：`--brute` 下 BVH 版与暴力法渲染结果**逐像素完全一致**（0 不同像素），与 `test_ray` 的 BVH 一致性用例互相印证。
- **超采样**：`--samples 3` 让每个像素发 9 条主光线，边缘明显更平滑（`tests/test_raytracer.cpp` 用 `n=1` 与 `n=3` 渲染同一场景，统计到 251/1728 个像素不同，且 `n=1` 与"直接单射线渲染"逐像素差 0）。

## 与后续的关系

本阶段完成后，`gfx` 已能**自立**渲染出带光照、阴影、反射、折射的光线跟踪图，不再依赖任何课程脚手架；`View::pixelToRay`、`Bvh`、`intersect*` 与新的 `shadeLocal` / `RayTracer` 全部来自库本身。
