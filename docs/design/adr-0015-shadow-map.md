# ADR-0015 — 光栅化路径的阴影（阴影贴图 / Shadow Map）

> **用途**：记录"光栅化路径的阴影方案"落位 `gfx` 的决策：为什么用阴影贴图而不是阴影射线、光源视角为什么取正交投影、自阴影（shadow acne）的两道防线（法向偏移 + 斜率缩放容差）怎么定、一张贴图与光源的对应关系、以及刻意不做的部分。
> **目标读者**：实现/使用光栅化阴影的人与 AI Agent。
> **关联文档**：[adr-0014](adr-0014-shaded-raster-pipeline.md)（光栅化着色管线，本方案直接复用）、[adr-0012](adr-0012-raytracing-lighting.md)（光照与"阴影测试回调"的分层纪律）、[adr-0006](adr-0006-camera-view.md)（View）；实现 [shadowmap.hpp](../../src/include/gfx/render/shadowmap.hpp)；测试 [test_shadowmap.cpp](../../tests/test_shadowmap.cpp)；教学主题 [shaded-raster](../../tutorials/shaded-raster/README.md)。

> **状态**：✅ 采纳（2026-10-09）。落地：`shadowmap.hpp` 的 `ShadowMap`（`configure` / `build` / `visibility` / `isShadowed` / `setNormalOffset` / `setDepthBias` / `setSlopeScale` / `setPcfRadius`）；配套把 `View::clipToPixel` 提为公开、新增 `View::forward()`。

## 背景

- 触发材料：ADR-0014 让光栅化路径能逐像素着色，但 `lighting.hpp` 的 `shadeLocal` 需要一个**阴影测试回调**；光线跟踪那条路用"阴影射线 + 场景求交"提供它，光栅化路径**没有场景求交**，该回调只能恒为"不遮挡"。
- 项目现状：已有完整的"View + DepthBuffer + 着色管线"，即"从一个视角把场景光栅化进深度缓冲"的能力。
- 缺口：需要一次**光源视角**的深度 pass，把"从光源看不见"变成逐片元可查询的判据。

## 决策

### D1：新建 `render/shadowmap.hpp`；深度 pass 直接复用 ADR-0014 的管线

- `build()` 就是"换个 View 再跑一遍 `fillTriangleShaded`"，只是片元着色器返回零色 —— 本 pass 只消费它的深度测试与写入。
- 理由：阴影贴图的全部机制（投影、近平面裁剪、深度插值、深度测试）都已经在 ADR-0014 里做过了；再写一套"只写深度的光栅化器"是重复劳动。这也顺带证明那条管线是**与用途无关**的。
- 代价：depth pass 会白算一遍片元颜色（返回零色 + 一次 `putPixel` 到临时画布）。在演示规模（2478 三角形 → 1024² × 2 张图）下总耗时仍在亚秒级，不值得为它开一条"无颜色"的特化路径。

### D2：光源视角取**正交投影**（等价平行光）；为此把 `View::clipToPixel` 提为公开并新增 `View::forward()`

- 阴影贴图需要"**带齐次 w 的裁剪空间点**"才能自己做透视除法与视口映射；`View::clipToPixel` 原先私有。ADR-0014 当时的做法是在 `shading.hpp` 里复刻这段映射（见 ADR-0014 D2）。现在**第三个**使用方出现了（本文件同时需要 `visibility` 的像素坐标与"1 texel = 多少世界单位/多少 NDC z"），故改为**把它提为公开的唯一实现**，并删掉 `shading.hpp` 里的复刻。
  - 判据：同一段公式被两处复刻是"可接受的实现细节"，被三处复刻就是 API 缺失。
- `View::forward()`（观察矩阵第 3 行取负）给出相机**世界空间视线方向**。正交光源下这就是"场景 → 光源"的常矢量，`ShadowMap` 用它算斜率容差，不必再让调用方多传一个方向参数。
- 局限（写进头文件注释）：正交贴图配点光源是"离得越远越准"的近似；真要点光源应改用立方体阴影贴图或透视贴图。斜率项依赖"方向处处相同"，也只对正交成立。

### D3：自阴影（acne）的两道防线 —— 法向偏移 + **斜率缩放**深度容差

自阴影的根因：**被接收的面自己也在贴图里**。若容差不够，"自己的深度"会被判成"比自己更近的遮挡物"。

1. **法向偏移**（`normalOffset`，世界单位）：采样点沿着色法向抬起 `d`，于是沿光方向的深度余量为 `d·(N·L)`。
2. **斜率缩放深度容差**（`slopeScale`，单位"texel"）：一个 texel 覆盖的深度范围随面与光线的夹角增大而增大（∝ tanθ）。容差取
   `bias = depthBias + slopeScale · texelWorld · min(tanθ, slopeCap)`，再按正交投影的 `2/(far−near)` 换算成 NDC z。
- **为什么必须有第 2 条**：掠射处 `N·L → 0` 时，第 1 条的贡献 `d·(N·L) → 0`，法向偏移**完全失效**；棱边与曲面上会留下椒盐状噪点（演示里实测：只做法向偏移时残留 335 个椒盐像素，加上斜率项后降到 95，且剩下的都在立方体轮廓上、对比度仅 ~11%）。
- **为什么要封顶**（`slopeCap`，默认 8）：掠射处该光源本来就照不亮，容差再大也不会被看见；但不封顶会把真阴影的边缘"溶掉"（漏光）。
- 参数一律用**世界单位 / texel**，不用 NDC：正交投影下 NDC z 与世界深度只差一个常量因子，用世界单位能让参数与"视体范围"解耦，也与"把场景整体缩放"无关。
- 顺序上先按法向偏移，再算法向与光线的夹角（用**着色法向**——法线贴图扰动后的更好，能一并压掉凹凸引起的自阴影）。

### D4：**一张贴图只服务一个光源**，由调用方负责"用哪张"

- 多光源要各建一张。`visibility` / `isShadowed` 只回答"对**这一个**光源是否被挡"。
- `shadeLocal` 的阴影回调签名是 `(p, dirToLight, distance)`，不含光源下标；演示的做法是**按方向匹配**（取 `dot(normalize(light.position − p), dirToLight)` 最大的那个光源）。这是调用方的编排策略，不上升为库 API —— 库不该假设"光源与贴图怎么配对"。
- 语义上这是"多重阴影"的常见做法：每个光源独立决定它那一份漫反射/高光是否被跳过。

### D5：PCF 用 3×3 平均（`pcfRadius`），而非单点比较

- 单点比较在阴影边缘是硬锯齿；半径 1 的 3×3 平均把边界软化一个 texel 左右。
- 返回值语义因此是**可见性**（1 = 全亮，0 = 全挡，中间 = 处于半影），`isShadowed` 只是 `visibility < 0.5` 的便利封装。
- 半径可调 (0..3)；`setPcfRadius(0)` 退化为单点比较。

### D6：已知边界（刻意不做）

- **不做背面剔除**：光源视角下正反两面都写深度。好处是单面几何（如演示里的地面）也能进图；代价是斜面上的自阴影要靠 D3 压掉。若要"只写背面"的经典变体，需要引入绕序约定，留待有明确需求时再加。
- **不做点光源**（立方体/透视贴图）、**不做级联贴图**（大场景的远近分辨率分配）。
- **贴图范围之外视为受光**：`depthAt` 越界返回远平面，故光源视锥外的片元不会被误判成阴影（代价：视锥外的遮挡物不产生阴影，需要调用方把正交范围开够）。

## 验证（可复现）

- 单元测试 `ctest -R test_shadowmap`（**447 checks，0 failures**）：
  1. **与解析求交逐点一致**：地面 + 悬浮盒子，对 121×121 个地面采样点用 AABB 光线求交做参照；"把盒子**收缩** 5 texel 后仍被光线命中 ⇒ 必须判为阴影"、"把盒子**膨胀** 5 texel 后仍打不中 ⇒ 必须判为受光"，容差带内的点跳过，故比较是**严格相等**（不是模糊阈值）。垂直光（阴影 = 正投影）与斜光两种情形都测，并检查斜光下阴影质心偏在光源反方向（−x/−z 侧）。
  2. **光源后方 / 视锥之外**：光在 y = 6 时，y = 7 的接收面必须为"受光"；正交范围（±6）之外的采样点必须为"受光"。
  3. **无自阴影 acne**：无遮挡物时，让一块**倾斜平面**自己进深度 pass 再采样自身（正是 acne 的触发方式），默认参数下 1701 个采样点**全部不受阴影**；把两道防线全部关掉后必然出现大量自阴影（> 50 个），只做法向偏移、不做斜率缩放则仍有残留 —— 用对照组证明防线确实在起作用，而不是场景恰好不出问题。
  4. **PCF 量化**：半径 r 时可见性只取 `1 − k/(2r+1)²`（逐点校验 401 个采样），且边界上确实出现中间值；半径 0 时不再出现中间值。
  5. **未配置行为**：未 `configure` 的贴图 `ready() == false`、`build()` 什么也不写、一切查询一律返回"受光"。
  6. **`View::forward()`**：默认视图为 (0, 0, −1)；`lookAt` 后与 `normalize(target − eye)` 的点积为 1。
- `ctest --test-dir build`：**16/16 通过**（原 15 + `test_shadowmap`）。
- 教学演示实跑（800×600；地面 6×6 四边形 + 立方体 6 面 + 球 28×44 经纬网格 = **2478 个三角形**、**436550 个着色片元**；2 个光源各一张 1024² 贴图）：
  - 开/关阴影（`--compare`）**25555 / 480000 像素不同（5.32%）**，最大通道差 188，平均差 3.10；
  - 其中**椒盐像素（4 邻域无差异）仅 95 个（0.0198%）**，且全部落在立方体轮廓上、对比度约 11%（远低于可见阈值）；
  - **不变式**：把两张图逐像素比较，"阴影图更亮"的像素数为 **0** —— 阴影只会**减少**某个光源的贡献，绝不会增加，这一条同时校验了深度比较的方向、PCF 的取值区间与"按方向匹配到正确光源"三件事。
