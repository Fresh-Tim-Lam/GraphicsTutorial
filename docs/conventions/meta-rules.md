# meta-rules.md — 规范元规则

> **用途**：规定"如何制定与维护规范"本身的规则，以及结论记录、违规后果分级与通用协作纪律。
> **目标读者**：需要新增/修订/废弃任何规范（conventions/、guides/、reference/ 等）的负责人与 AI Agent。
> **关联文档**：[docs-management.md](docs-management.md)；[collaboration.md](../guides/collaboration.md)（协作细则展开）。

> 状态：生效中（核验于 2026-09-09）。

## 规则

1. **结论即落盘，同步认知**：讨论产生明确结论（采纳/拒绝/暂缓）后，须在 **1 次对话轮内**更新到对应规范文档；Agent 响应前先读最新规范；规范变更后输出 `[上下文已同步] 规则 xxx 已更新（时间）`。
2. **结论必有标记**：议题最终状态显式标记 `✅ 采纳 / ❌ 不采纳 / ⏳ 暂缓`（暂缓注明阻塞项）；未标记视为未关闭。
3. **规则依附场景**：每条规则必须关联具体开发场景，标题/说明带 `[场景名]` 前缀；纯抽象规则不写入。
4. **首行释用途**：见 docs-management 头部三要素；违反则视为未完成，不得正式引用。
5. **违规后果分级**：轻度（1 轮内未更新）→ 暂停当前讨论先补更新；重度（跨对话未更新）→ 结论视为未生效需重新确认。
6. **通用协作纪律**：存疑即停、先问后做；反问必须带选项并给推荐；先用尽自解手段再问；对齐后按结果执行；低风险事务不阻塞等待。细则展开到 collaboration.md。
7. **单一事实源纪律**：版本号、日志规范、导入格式等任何"多处需要一致"的信息只放一处权威源，其余引用指针。
