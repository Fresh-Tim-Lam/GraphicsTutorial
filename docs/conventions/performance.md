# performance.md — 性能相关写法与结论记录规范

> **用途**：规定**性能敏感写法**的取舍原则与"性能结论如何落盘"，避免同类优化被反复争论、或凭直觉改热路径（含矩阵/变换构造、逐像素与逐点循环、批处理路径）。
> **目标读者**：修改 gfx / gfx_math 热路径的开发者与 AI Agent；需要引用性能依据写教程/评审的人。
> **关联文档**：[meta-rules.md](meta-rules.md)（规范元规则：结论落盘/标记/依附场景）；[directory-organization.md](directory-organization.md)（artifacts 与 benchmarks 的归属）；[adr-0002-template-math.md](../design/adr-0002-template-math.md)（数学层结构与 `math::detail` 定位）；基准与基线 [benchmarks/bench_rotate.cpp](../../benchmarks/bench_rotate.cpp)。

> 状态：生效中（核验于 2026-09-09）。

## 1. 适用范围

约束对象 = **性能敏感路径上的写法**，当前主要指：

| 路径 | 例子 |
|------|------|
| 矩阵/变换构造 | `math::transform2d/3d` 各工厂函数、`Transform<N>` 折叠 |
| 逐点 / 逐像素循环 | `Canvas::putPixel` 及其上层绘制原语、批处理 `batchTransform` |
| 数据搬运与布局 | 点视图（连续 / 带步长 AoS）、批量后端分派 |

非热路径（初始化、一次性配置、教学演示）**不受 P1/P2 约束**，以可读性优先。

## 2. [矩阵构造] ✅ 采纳（2026-09-09）

### P1 矩阵字面量不是零成本：同一结果只构造一次

- **现象**：`Mat<N>` 的行字面量走 `Mat(std::initializer_list<...>)` 构造函数（**运行时循环填值**），不是聚合初始化的直接存储。多构造一个矩阵要真花钱。
- **规则**：禁止"先调用某个构造函数拿到矩阵，再拆字段/补一项后二次组装"；应在**同一个字面量**里一次写全所有元素。
- **实测依据**（GCC 14.2 / MinGW-w64 / `-O2` / 5,000,000 次，2026-09-09；复现命令见 [benchmarks/README.md](../../benchmarks/README.md)）：

  | 写法（`rotate(rad, axis, center)` 实现） | ns/call |
  |------|---------|
  | 复用式：先 `rotate(rad, axis)`，再 `mat-vec` 求 `R·c` 填平移列 | 49.5 |
  | **纯展开式：16 项在同一字面量内写全** | **43.1** |

  两者结果**逐元素完全相同**（差异 0）；差距 ~13% 全部来自"少构造一次 `Mat4`"。
- **例外**：非热路径按可读性优先，不为省一次构造牺牲表达清晰度；先测量再决定。

### P2 同一算法公式只保留一份

- **规则**：同一算法/公式不得在多个函数里各写一遍。做法二选一：
  1. 让"最通用"的重载成为**唯一实现**，其余重载委托它（推荐：避免新增内部类型）；
  2. 将系数/中间量抽到 `math::detail`（见 [ADR-0002](../design/adr-0002-template-math.md) D3）。
- **落点示例**：轴角旋转以 `transform3d::rotate(rad, axis, center)` 为唯一实现（Rodrigues 系数为具名局部 + 单字面量写全）；`rotate(rad, axis)` 委托它（`center = 原点`）。实测委托代价 ≈ +2 ns/次（40.7 → 42.8），换取公式只写一份——**推荐接受**；若为省这 2 ns 而复制公式，即违反本规则。

## 3. [变换消费] ✅ 采纳（2026-09-09）

### P4 折叠结果要缓存；批量优先于逐点

- **规则**：变换链只记录、不计算；`matrix()` 折叠必须**惰性 + 缓存**（追加只让缓存失效），避免"每次消费重新折叠"。
- **消费选择**（同一变换作用 N 个点时）：
  | 路径 | 实测（N=1e5，3 步变换，-O2） | 建议 |
  |------|------------------------------|------|
  | 批量 `t.apply(in,out,count,stride)` | 3.6 ns/点 | **首选**（还可经后端钩子走 SIMD/GPU）|
  | 逐点 `t.apply(p)` / `p.apply(t)` | 5.2 / 9.0 ns/点 | 可用（折叠已缓存）|
  | 每次重新折叠/重建矩阵 | 38.9 ns/点 | 禁止（F 路径）|
  | 每点新建一条链 | 110 ns/点 | 禁止（反模式，链应挂在变换对象上复用）|
- **反例**：在循环里新建 `Transform` 或反复调用 `matrix()` 而不缓存 —— 前者每点付堆分配，后者每点付 k−1 次矩阵乘。
- **基线**：[benchmarks/bench_point_apply.cpp](../../benchmarks/bench_point_apply.cpp)（数字唯一事实源）。

## 4. [性能结论] 记录方式

- **P3 结论必须可复现**：任何"更快/更省"的结论落文档时，必须同时给出：
  1. **可复现基准**——放 [benchmarks/](../../benchmarks/README.md)（含构建/运行命令），基线数字写在基准源文件头部（**单一事实源**，文档只引用不复制）；
  2. **测量条件**——编译器与版本、优化档、迭代次数、测量日期。
- **反例**：只写"这样更快"而无基准与条件 → 按 [meta-rules.md](meta-rules.md) 第 5 条视为未完成（轻度违规）。
- **与临时实验的分工**：一次性试探脚本放 `artifacts/`（gitignore）；**一旦成为结论依据，必须移入 `benchmarks/`**（见 directory-organization.md）。
- **改结论**：结论变化时更新对应规范条目 + 重跑基准更新基线，并在条目内标注新的核验日期。

## 4. 违规后果

- 未按 P1/P2 写热路径代码（重复构造、复制公式）→ 按 meta-rules 违规分级处理；
- 性能结论缺基准或测量条件 → 结论视为未生效，需补齐后重新确认。
